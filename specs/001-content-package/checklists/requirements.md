## Notes

**Iteration 1 — one item outstanding.**

**Open:** *No [NEEDS CLARIFICATION] markers remain.* One clarification is
outstanding — **the authoring surface** (Question 1). It is genuinely undecided
rather than an unstated default: `resources/characters/hero-stats.xlsx` is
currently *generated by* `tools/build-hero-stats.py`, so no path exists from a
designer's edit to loadable content, and the two candidate directions produce
materially different packages.

Everything else passed on the first iteration. Two notes on judgment calls:

- **"No implementation details"** — the spec names `Zod` nowhere and describes
  validation behaviorally. It does cite `resources/characters/MATCHUPS.md` and
  `tools/build-hero-stats.py` as existing artifacts, which is context rather than
  implementation direction.
- **"Written for non-technical stakeholders"** — the audience for this particular
  feature is the designer authoring heroes, not a player. The spec is written for
  that reader; it avoids naming a language, a library or a file format.

**Provisional values are recorded as assumptions rather than clarifications.**
Stats, reach and power magnitudes are all known-provisional pending the
hero-numbers pass. They do not block specification because SC-008 requires the
schema to absorb them without a consuming-feature change.

THE FLOWS
What talks to what, which way, and in what order.
1
A battle turn
intent → API → replay log → resolver → append → one packet back
The client sends only battleId, heroId, powerId, targetId. The packet covers the player's action and everything following it until the next real choice.
STATE IS RE-DERIVED FROM THE LOG EVERY REQUEST — ONE SOURCE OF TRUTH, AND IT CANNOT DESYNCHRONIZE
2
Chat
POST → API authorizes · charges · persists → calls the classifier → publishes → broker fans out
Clients subscribe; clients never publish. The broker's only job is fan-out.
CORRECTNESS, NOT HARDENING — SOME POSTINGS COST CURRENCY, SO DIRECT PUBLISHING WOULD BYPASS THE CHARGE
3
Sign-in
ID token or session ticket → API verifies with the provider → upsert → our own signed token
Two providers, one account. Refresh tokens live in Postgres.
ACCOUNT LINKING IS A FIRST-CLASS REQUIREMENT, NOT A LATER FEATURE
4
Purchase
checkout at the provider → webhook to the API → entitlement granted
The merchant of record owes the tax and absorbs the chargebacks.
THE ENTITLEMENT BELONGS TO THE ACCOUNT, NEVER TO THE STOREFRONT — A BROWSER PURCHASE IS PRESENT IN THE STEAM BUILD
5
Replay lifecycle
on completion → metadata row to Postgres (permanent) + event log to blob (7 days)
A scheduled job deletes expired logs.
DRIVEN BY A POSTGRES QUERY, NEVER BY LISTING THE BUCKET — THE DATABASE STAYS THE AUTHORITY ON RETENTION
EASY TO GET WRONG
Check the drawing against these, not the inventory.
The relational store is not uniformly permanent. Battle metadata is; chat is retention-bound in its own tables. One “kept forever” label across the whole store would mislead anyone building the schema.
“The API moderates” is an outbound call. If the chat flow shows no arrow leaving Zone 2 for a classifier, the diagram is incomplete.
The API never holds an open socket. The client's realtime connection goes directly to the broker — two separate arrows, not one line through the API.
Replays are stored, never regenerated. Played back as recorded, so a balance patch can never change the outcome of a past battle.
The seed line is a boundary, not a data flow. Nothing crosses it in either direction.
Rules appear in two places on purpose. Not duplication to flag — one package imported by both sides.
Steam is not a second backend. A second shell and a second identity provider. Everything behind the API is identical.
